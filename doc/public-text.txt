APP STORE LISTING (iOS)
-----------------------
(paste into App Store Connect: the description field; the Play text minus what
iOS does not have: share-to-AIS, folder sync and keep-a-copy, replaced by the
file export line. Keep it in step with full_description.txt.)

AIS keeps the things you want to find again: links, notes, file paths, commands, passwords. You save each one under tags you choose, and find it later by typing those tags.

Examples
wifi guest: the guest Wi-Fi password
recipe chicken: a link to the recipe
passport documents: where the scan is
car insurance: the policy number

Type "recipe" and you get every recipe. Type "recipe chicken" and you get what was saved under both.

Private
Everything stays on the phone. No account, no ads, no tracking, no server, and the app collects no data. A password or other secret can be locked: it then shows only after you type the password you chose.

Yours
Your notes are plain text: you can read them, export them, and open them without AIS. Plain text has been readable since the 1960s on any machine, so your notes outlive the app. The same notes open on an iPhone, and the desktop versions for Linux, macOS and Windows show them in your browser.

Sync and backup, only when you ask
- Between two of your devices on the same Wi-Fi: one shows a code, the other scans it. The transfer is direct and end-to-end encrypted.
- Export to a file, kept in Files or sent anywhere, and import it back. Nothing is in iCloud.

Also
- Import a browser's bookmarks file, or what Pocket, Instapaper or Raindrop export.
- A timeline of everything saved, with a date range.
- A list of every tag you have used.
- Search inside the saved text when no tag matches.
- Voice search, recognised on the device.
- Light and dark theme.

Free and open source (GPL 2 or later, or MIT). Source code, documentation and the desktop versions: https://github.com/Anode1/ais



SYNC, DESCRIBED
---------------
TECHNICAL for a technical audience, PLAIN for everyone else.

=== TECHNICAL ===

AIS LAN sync is a direct device-to-device exchange over the local network: no
cloud, no relay, no dependencies. One device hosts an ephemeral single-client
TCP server (ais --sync --serve, or Host in the app) and shows a pairing token
and a URL (the app also as a QR); the other joins (ais --sync
http://host:port --token T, or Join in the app), and both merge each other's
records in one round. A one-way copy is ais --export --serve on one side and
ais --import http://host:port --token T on the other. Pairing is manual, there
is no auto-discovery, and it works on the same LAN only (no internet, relays,
or NAT traversal).

Security is a pre-shared one-time token plus challenge-response auth: the server
sends a random challenge, the client returns a keyed proof of token+challenge,
so the token itself is never transmitted. The payload (the export stream: live
records A|ts|keys|value and tombstones D|ts|hash) is sealed as an AEAD document
under a key derived from the token. A wrong token or any tampering is rejected at
decryption, before anything is merged. So the transfer is end-to-end encrypted
and authenticated between the two devices.

Each receiver merges the stream into its store: tombstone-union, last-write-wins
by timestamp, content-addressed and idempotent (re-syncing is safe; only
genuinely new records land). Only non-rebuildable data moves (store, tombstones,
saved blobs); the index is rebuilt locally. The server is single-use and exits
after one transfer.

Folder sync is the always-on alternative: each device writes a framed bundle
into a folder that a folder-sync tool such as Syncthing shares between them
(ais --sync-folder DIR, or Sync > Set a sync folder in the app) and merges the
other devices' bundles. The app runs a pass at every open and after every
change.

=== PLAIN ===

Sync is optional, directly between your own devices on the same Wi-Fi. One
device shows a code (and a QR); the other joins with it, and both end up with
each other's data over your local network. The transfer is end-to-end
encrypted with a one-time token only your devices share, and a wrong token is
rejected before any data is read. No cloud, no account, nothing passes through
us. For background sync, share a folder between your devices with a tool such
as Syncthing and point AIS at it; the app then syncs at every open and after
every change.
