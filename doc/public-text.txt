AIS: ready-made text for stores and public answers
==================================================
Paste-ready copy meant to leave the repo: the Play Store listing, and two blocks
for answering "how does sync work". What they describe is specified in
PRIVACY.md and doc/dev/SYNC_PROTOCOL.md; when the app changes, those move first
and this file follows.


GOOGLE PLAY STORE LISTING
-------------------------
(paste into Play Console: Grow > Store presence > Main store listing)

App name:
AIS

Package name (permanent):
com.aisindex.ais

Short description (max 80 chars):
Save links, notes and passwords under your own tags. Offline, no account.

Full description (max 4000 chars). The paragraphs are single lines on purpose:
Play keeps every line break, so text wrapped at 80 columns shows as ragged
lines in the store.

AIS keeps the things you want to find again: links, notes, file paths, commands, passwords. You save each one under tags you choose, and find it later by typing those tags.

Examples
wifi guest: the guest Wi-Fi password
recipe chicken: a link to the recipe
passport documents: where the scan is
tunnel prod ssh: the command you look up every time

Type "recipe" and you get every recipe. Type "recipe chicken" and you get what was saved under both.

Private
Everything stays on the phone. No account, no ads, no tracking, no server, and the app collects no data. Passwords and other secrets are encrypted with a passphrase only you know.

Yours
The index is plain text: you can read it, export it, and open it without AIS. Plain text has been readable since the 1960s on any machine, so the index outlives the app. The same index opens on Linux and macOS, in a terminal and in a browser.

Sync and backup, only when you ask
- Between two of your devices on the same Wi-Fi: one shows a code, the other scans it. The transfer is direct and end-to-end encrypted.
- Through a folder that Syncthing or a cloud drive carries.
- Keep a copy in a folder, so the index survives uninstalling the app.

Also
- Share a link or text to AIS from any other app.
- A timeline of everything saved, with a date range.
- A list of every tag you have used.
- Search inside the saved text when no tag matches.
- Voice input, recognised on the device.
- Light and dark theme.

Free and open source (GPL 2 or later, or MIT). Source code, documentation and the desktop versions: https://github.com/Anode1/ais

SYNC, DESCRIBED
---------------
TECHNICAL for a technical audience, PLAIN for everyone else.

=== TECHNICAL ===

AIS LAN sync is a one-shot, direct device-to-device transfer over the local
network: no cloud, no relay, no dependencies. One device runs an ephemeral
single-client TCP server (ais --export --serve) and shows a pairing token and a
URL (as text or QR); the other device pulls and merges (ais --import
<host:port> --token T). Pairing is manual, there is no auto-discovery, and it
works on the same LAN only (no internet, relays, or NAT traversal).

Security is a pre-shared one-time token plus challenge-response auth: the server
sends a random challenge, the client returns a keyed proof of token+challenge,
so the token itself is never transmitted. The payload (the export stream: live
records A|ts|keys|value and tombstones D|ts|hash) is sealed as an AEAD document
under a key derived from the token. A wrong token or any tampering is rejected at
decryption, before anything is merged. So the transfer is end-to-end encrypted
and authenticated between the two devices.

The receiver merges the stream into its store: tombstone-union, last-write-wins
by timestamp, content-addressed and idempotent (re-syncing is safe; only
genuinely new records land). Only non-rebuildable data moves (store, tombstones,
saved blobs); the index is rebuilt locally. The server is single-use and exits
after one transfer.

=== PLAIN ===

Sync is optional and on-demand, directly between your own devices on the same
Wi-Fi. One device shows a code (and a QR); the other uses it to pull the data
over your local network. The transfer is end-to-end encrypted with a one-time
token only your devices share, and a wrong token is rejected before any data is
read. No cloud, no account, nothing passes through us, and it is a one-time
manual transfer, not always-on background sync.
